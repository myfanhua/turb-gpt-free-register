# 账号注册地址显示设计

## 目标

为新注册成功的账号记录当次注册代理的实际出口位置，并在 WebUI 账号列表中显示国家/地区；表格空间允许时同时显示公网 IP。旧账号没有位置数据时显示 `-`，不执行历史补查。

## 范围

- 只处理功能上线后新注册成功的账号。
- 位置检测使用该账号当次注册所用的 `registration_proxy`，不使用本机直连结果，也不根据当前配置反推历史位置。
- 保存国家代码、国家名称、地区名称和公网 IP。
- 位置查询失败不影响账号注册、Token 保存、Codex 流程或套餐复检。
- 不修改旧账号记录，不增加批量补查入口。

## 方案选择

采用“通过当次注册代理查询实际出口位置”的方案。

未采用的方案：

1. 从代理用户名中的 `region-US` 等参数推断：速度快，但不能反映代理实际出口异常或分流错误。
2. 直接记录当前配置国家：实现简单，但配置变化后不能准确表示账号注册当时的位置。

## 架构

新增一个独立的位置解析模块，负责通过指定代理请求 IP 地理信息服务并返回规范化结果。注册流程在取得 Access Token、且 Roxy 环境仍保持打开时调用该模块，然后把结果随账号数据一起保存。数据库文件层只存储普通字段，WebUI API 将这些字段加入账号列表的轻量对象，前端增加“注册地址”列。

位置解析与注册流程解耦：解析模块发生超时、响应异常、字段缺失或服务不可用时返回空结果并记录警告，注册主流程继续保存账号。

## 数据模型

在新账号记录中按有值写入以下字段：

- `registration_country_code`：两位国家代码，例如 `US`。
- `registration_country`：用于界面显示的国家名称，例如 `美国`。
- `registration_region`：州、省或地区名称，例如 `California`。
- `registration_ip`：当次代理出口公网 IP。

旧账号不补字段。读取时所有字段均为可选字段。

位置解析结果使用如下结构：

```python
{
    "country_code": "US",
    "country": "美国",
    "region": "California",
    "ip": "203.0.113.10",
}
```

国家名称优先由本地国家代码映射生成，避免界面直接依赖第三方服务返回的英文名称。未知代码回退显示国家代码；没有国家代码时显示地区；两者都没有时显示 `-`。

## 数据流

1. Roxy 注册流程确定本次使用的 `registration_proxy`。
2. 账号完成注册并取得 Access Token。
3. 使用 `registration_proxy` 请求位置服务，设置短超时且不进行长时间重试。
4. 将规范化位置结果传入 `save_account_data()`。
5. `insert_account()` 把非空位置字段写入账号 JSON 记录。
6. `/api/accounts` 的轻量列表对象返回位置字段，不返回代理账号密码。
7. 账号表“注册地址”列主行显示国家，次行在有空间时显示 IP；完整国家、地区和 IP 放入单元格 `title`。

## WebUI

账号表在“来源”之后增加“注册地址”列，宽度约 140px：

- 主行：国家名称，如 `美国`。
- 次行：公网 IP；没有 IP 时不渲染次行。
- 悬停文本：`美国 · California · 203.0.113.10`，自动忽略空字段。
- 旧账号或查询失败：显示灰色 `-`。

表格已有横向滚动容器，因此不压缩邮箱、套餐和操作列。空列表行的 `colspan` 同步增加一列。

## 位置查询策略

- 请求必须显式使用当次 `registration_proxy`。
- HTTP 与 SOCKS 代理沿用项目现有 `requests` 代理配置能力。
- 单次短超时；失败后不阻塞注册流程进行多轮等待。
- 响应必须是 JSON 对象，IP、国家代码和地区字段分别规范化。
- 不在日志中输出代理密码；日志只记录查询成功的国家代码/IP或简短失败原因。
- 服务地址集中定义，便于测试替换和后续维护。

## 错误处理

- 没有注册代理：跳过查询并保存空位置。
- 请求超时、网络错误或非成功响应：记录警告，保存空位置，继续注册。
- JSON 无效：记录警告，保存空位置，继续注册。
- 只有部分字段：保存可用字段，界面按降级规则显示。
- 账号保存失败仍按现有注册错误流程处理；位置查询不会改变原有异常边界。

## 测试

1. 位置客户端通过指定代理请求，并规范化国家代码、地区和 IP。
2. 位置请求失败时返回空结果，不向注册流程抛出阻断性异常。
3. `save_account_data()` 和 `insert_account()` 正确保存新位置字段。
4. 旧账号缺少字段时账号 API 正常返回。
5. `/api/accounts` 轻量对象包含位置字段，但不泄露 `proxy_used`。
6. 前端渲染包含“注册地址”列、国家、可选 IP，以及正确的空数据 `colspan`。
7. 全量测试确保注册、账号列表、Token 复制及现有分页行为不受影响。

## 验收标准

- 新注册账号在账号页显示当次实际代理出口国家。
- 查询到 IP 时，同一单元格次行显示 IP。
- 旧账号显示 `-`。
- 位置服务故障时账号注册仍可完成。
- 账号列表 API 不返回代理凭据。
- 全量自动化测试通过。
