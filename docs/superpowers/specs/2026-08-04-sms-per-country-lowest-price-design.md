# SMS 按地区实时最低价取号设计

## 背景

当前流程先通过 `getPrices` 选择地区，但真正调用 `getNumber` 时只传递全局
`SMS_MAX_PRICE=0.11`。地区报价没有继续传入取号请求，因此即使哥伦比亚的
最低报价为 `$0.055`，平台仍可分配该地区内不超过 `$0.11` 的更高价格号码。
历史订单已出现同为哥伦比亚、实际费用分别为 `$0.055` 和 `$0.0944` 的情况。

## 目标

- 全局最高价继续保持 `$0.11`。
- 每次从已配置的优选地区中选择当前最低报价。
- 取号时使用所选地区的实时最低报价作为本次请求的 `maxPrice`。
- 地区最低价变化时自动使用新价格，但始终不超过全局最高价。
- 报价超限、无库存或取号失败时不扩大价格范围，刷新报价后切换候选地区。
- 调查和自动化测试不得真实取号。

## 非目标

- 不改变国家优先列表及失败切换次数的配置入口。
- 不改变短信等待、取消和完成状态流程。
- 不自动提高全局最高价。
- 不增加运营商手动选择功能。

## 方案

### 报价选择

`PreferredCountrySelector` 不再只返回国家代码，而是保留并返回选中的
`SmsCountryOffer`，其中包含：

- `country_code`
- `price`
- `available_count`

候选报价必须同时满足：

1. 国家位于 `SMS_PREFERRED_COUNTRIES`；
2. 库存大于零；
3. 报价不超过 `SMS_MAX_PRICE`；
4. 国家未因当前任务的失败阈值被临时排除。

符合条件时按价格升序选择；同价时按用户保存的国家顺序选择。

### 取号限价

`acquire_number` 增加可选的单次 `max_price` 参数。兼容平台取号时：

```text
request_max_price = min(selected_offer.price, SMS_MAX_PRICE)
```

由于候选报价在选择阶段已经验证不超过全局最高价，正常情况下请求限价就是
所选地区的实时最低报价。例如：

- 哥伦比亚报价 `$0.0275`：请求 `maxPrice=0.0275`
- 哥伦比亚报价 `$0.055`：请求 `maxPrice=0.055`
- 哥伦比亚报价 `$0.0944`：请求 `maxPrice=0.0944`
- 哥伦比亚报价 `$0.12`：排除该地区，不调用取号接口

未传入单次 `max_price` 的其他调用保持现有行为，继续使用全局
`SMS_MAX_PRICE`，避免破坏其他接码提供方和旧调用方。

### 价格刷新与失败处理

- 每次首次取号前强制刷新候选地区报价。
- `NO_NUMBERS` 或地区失败达到切换阈值后，强制刷新报价并重新选择。
- 报价接口暂时不可用时，不按保存顺序盲取，因为此时没有可靠的地区最低价；
  本次手机号验证以明确错误停止。
- 所有地区报价均超过 `$0.11` 或无库存时，不调用 `getNumber`，返回包含各地区
  排除原因的错误。
- 单次取号请求仍由 `maxPrice` 限制，避免报价查询与取号之间发生价格上涨时取得
  更贵号码。

## 日志

选择地区时记录：

```text
country=33 quoted_price=0.055 request_max_price=0.055 stock=COUNT reason=lowest_price
```

日志不得记录 API Key。取号成功日志继续记录激活编号和号码，并附加本次请求限价，
便于用户将平台订单费用与程序选择结果对应。

## 接口变化

### `PreferredCountrySelector`

- 新增返回报价对象的方法，供新流程使用。
- 保留现有返回国家代码的兼容入口，避免无关调用方一次性变更。
- 当前国家的第二次尝试必须复用刷新后同一国家的最新合格报价，不复用旧价格。

### `sms_provider.acquire_number`

新增关键字参数：

```python
max_price: str | Decimal | None = None
```

- 有值：本次请求使用该限价。
- 无值：回退到 `SMS_MAX_PRICE`。

## 测试

自动化测试使用假 HTTP 响应，覆盖：

1. 哥伦比亚报价 `$0.055`、全局上限 `$0.11` 时，`getNumber.maxPrice` 为
   `$0.055`。
2. 地区报价低于 `$0.055` 时，取号限价使用更低报价。
3. 地区报价高于 `$0.055`、但不超过 `$0.11` 时，允许按该地区最低价取号。
4. 报价高于 `$0.11` 时，不调用 `getNumber`。
5. 多个地区同价时遵循保存顺序。
6. `NO_NUMBERS` 后刷新报价并切换到新的最低价地区。
7. 报价接口失败时停止，不按全局 `$0.11` 盲取。
8. 未传单次限价的旧调用仍使用全局配置。

## 验收标准

- 取号请求的 `maxPrice` 与所选地区当次最低报价一致。
- 任意取号请求的 `maxPrice` 不超过 `$0.11`。
- 哥伦比亚报价为 `$0.055` 时，不再发出 `maxPrice=0.11` 的请求。
- 所有新增和现有测试通过。
- 验证过程不产生真实短信订单或费用。
