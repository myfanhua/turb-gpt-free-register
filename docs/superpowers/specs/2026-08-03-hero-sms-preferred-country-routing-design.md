# HeroSMS 优选国家最低价取号设计

## 目标

为当前 HeroSMS/SMS-Activate 兼容接码通道增加优选国家动态选路：用户在 WebUI 中勾选多个优选国家，系统只在这些国家中选择有库存且未超过最高单价的最低价号码。同一国家连续两个实际号码失败后，本次 Codex 手机验证任务切换到其他优选国家中当时最便宜的国家。单账号默认最多使用五个实际号码。

该功能只改变 Codex 手机验证阶段的取号策略，不改变邮箱 OTP、Roxy 浏览器、Codex callback、Token 保存或其他接码通道的行为。

## 已确认的产品规则

1. 优选国家通过 WebUI 的可搜索多选框配置。
2. 每次开始手机验证时，在优选国家范围内按实时价格和库存选路。
3. 同一国家连续两个实际号码失败后，暂时排除该国家并重新选择最低价国家。
4. 默认总取号尝试次数为五次，仍可通过现有“换号重试次数”配置调整。
5. `NO_NUMBERS`、价格接口异常等发生在成功取得号码之前的错误不占用实际号码尝试次数，也不累计“连续失败”次数。
6. 当前国家第一次实际号码失败后，第二次仍优先留在该国家；第二次失败后才切换国家。
7. 无库存或价格已经超过最高单价时允许提前切换国家，不必等待该国家累计两次失败。

## 配置与兼容性

### 新增配置

- `SMS_PREFERRED_COUNTRIES: list[str]`
  - 保存用户选中的 provider country code。
  - 在 `.env` 中按现有列表配置格式持久化。
  - 为空时自动回退为 `[SMS_COUNTRY]`，保证旧配置继续工作。
- `SMS_COUNTRY_FAILURE_SWITCH: int = 2`
  - 同一国家连续实际号码失败多少次后切换。
  - WebUI 标签为“连续失败换国家”。

### 调整默认值

- `SMS_MAX_RETRIES` 源码默认值由 `10` 调整为 `5`。
- 当前 worktree 的 `.env` 已明确配置为 `3`，本次上线时同步调整为 `5`，保证当前 WebUI 立即显示并使用五次。
- 其他环境已经在 `.env` 中明确配置的值不由程序自动覆盖；WebUI 可随时改成其他总次数。

### 适用通道

- `grizzly`、`sms_activate`、`hero_sms` 使用动态价格选路。
- `l`、`h` 继续使用现有固定国家/项目逻辑，不调用价格接口。

## WebUI 设计

在“配置 → 接码平台 → 通用接码”中增加“优选国家”控件：

- 搜索框按国家名称或 country code 过滤。
- 列表项显示国家名称和 provider country code。
- 已选国家以紧凑标签展示，可直接移除。
- 保存时写入 `SMS_PREFERRED_COUNTRIES`。
- 首次使用且列表为空时，将当前 `SMS_COUNTRY` 显示为已选项。
- 国家目录由后端的 provider country catalog 接口提供并做缓存。
- 国家目录暂时加载失败时，已经保存的 country code 仍可显示、保存和删除；界面显示刷新失败提示，不清空原选择。

“换号重试次数”默认展示为 `5`，“连续失败换国家”默认展示为 `2`。不增加额外的价格缓存、轮换周期等高级设置，保持日常操作简单。

## 后端组件

### 1. 国家目录与报价读取

在 `core.sms_provider` 中增加清晰的 provider 能力：

- `list_country_catalog(http=None)`：返回标准化的国家列表。
- `get_country_offers(countries, service=None, http=None)`：读取指定优选国家的价格与库存，返回标准化报价。

标准化报价至少包含：

- `country_code`
- `price`
- `available_count`

价格使用 `Decimal` 比较，避免浮点排序误差。异常响应、缺少服务价格、不可解析价格和负库存均视为该国家本轮无有效报价。

报价使用进程内约三十秒短缓存。开始手机验证、缓存过期或国家因连续失败被排除时重新评估；缓存时长作为内部常量，不暴露到 WebUI。

### 2. 单任务国家选择器

每个 Codex 手机验证任务创建独立的 `PreferredCountrySelector`，不在账号之间共享失败状态。选择器维护：

- 用户优选国家顺序。
- 每个国家的连续实际号码失败次数。
- 本任务暂时排除的国家集合。
- 当前固定国家。
- 最近一次有效报价。

选择规则：

1. 当前国家失败次数为一且仍有库存、价格未超上限时，第二次继续使用当前国家。
2. 当前国家失败次数达到 `SMS_COUNTRY_FAILURE_SWITCH` 后，将其加入本任务排除集合。
3. 从未排除且有效的优选国家中，按价格升序选择。
4. 价格相同时，按用户在多选框中的保存顺序选择。
5. 无库存或超过 `SMS_MAX_PRICE` 的国家不进入候选集合。
6. 所有优选国家都被排除且总尝试次数仍未耗尽时，清空临时排除集合并重新按实时最低价开始一轮。

例如三个国家 A、B、C 在每次切换时依次最便宜，默认五次尝试的典型顺序为：

```text
A → A → B → B → C
```

两个国家时可能为：

```text
A → A → B → B → A
```

### 3. 取号接口衔接

保留 `acquire_number(..., country=...)` 现有显式国家参数。Roxy Codex 手机验证循环在每次实际取号前向选择器请求国家，再把 country code 传入 `acquire_number`。

成功取得 activation ID 后才增加总尝试次数。以下情况的处理为：

- OpenAI 拒绝号码、短信超时、手机 OTP 被拒或号码流程异常：记录该国家一次实际号码失败，取消号码并执行换号策略。
- `NO_NUMBERS`：本轮立即把该国家标记为无库存并选择其他国家，不增加总尝试次数。
- `NO_BALANCE`：立即结束手机验证，不继续请求其他国家。
- provider HTTP/API 异常：使用最近有效报价；没有缓存时按用户保存顺序尝试优选国家，不伪造价格。
- 所有优选国家无库存或超过最高价：返回包含各国过滤原因的明确错误，不调用 `getNumber`。

成功完成手机验证后沿用现有 `complete(status=6)`；失败号码沿用后台等待并 `cancel(status=8)` 的释放逻辑。

## 日志与可观察性

新增结构化但易读的日志：

- 本任务优选国家列表。
- 每轮有效报价摘要：国家、价格、库存。
- 选中国家及原因：最低价、同国家第二次、缓存回退或顺序回退。
- 某国家连续失败计数和被暂时排除事件。
- 无库存、超过最高价和全部候选不可用的汇总原因。

API key 等秘密配置不写入日志。现有手机号与 OTP 日志清理不属于本功能范围。

## 测试策略

### 单元测试

1. 解析 HeroSMS/SMS-Activate 兼容价格响应。
2. 在优选国家内选择有库存的最低价国家。
3. 排除超过 `SMS_MAX_PRICE` 的报价。
4. 同价时按用户保存顺序选择。
5. 第一次失败继续当前国家，第二次失败切换国家。
6. `NO_NUMBERS` 立即换国家且不消耗实际号码次数。
7. 所有国家暂时排除后重新开始一轮。
8. 价格接口失败时使用缓存；无缓存时按保存顺序回退。
9. `NO_BALANCE` 在 Roxy 路径立即终止。
10. 空优选列表回退到旧的 `SMS_COUNTRY`。
11. `l`、`h` 通道不进入动态价格逻辑。

### WebUI/API 测试

1. 国家目录接口返回标准化选项并隐藏秘密配置。
2. 多选国家可保存、重新加载和清空。
3. 旧配置首次加载时自动展示原 `SMS_COUNTRY`。
4. 默认 `SMS_MAX_RETRIES=5`、`SMS_COUNTRY_FAILURE_SWITCH=2`。

### 回归验证

- 运行完整 Python 测试套件。
- 用 mock provider 完成 A、A、B、B、C 的五次失败路由验证。
- 用单国家旧配置完成一次成功取号和收码流程验证。
- 人工检查 WebUI 多选控件在保存和刷新后状态一致。

## 非目标

- 不跨账号统计国家成功率。
- 不根据历史成功率修改价格权重。
- 不自动修改用户的优选国家列表。
- 不改变 Kakao 提链、套餐查询或注册代理逻辑。
- 不为 L/H 通道推断实时价格。
