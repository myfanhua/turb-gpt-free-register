# Kakao Provider 默认使用韩国代理池设计

## 目标

Kakao 提链 provider 默认使用项目现有 `PROXY_POOL`。用户的代理池已配置为韩国出口，因此不再增加国家选择或 Kakao 专用代理输入框。

## 配置与界面

- 新增布尔配置 `KAKAO_EXTRACT_USE_PROXY_POOL`，默认值为 `True`。
- WebUI「提链」配置组增加「Kakao API·使用代理池」开关。
- 开启时读取现有 `PROXY_POOL`；关闭时 Kakao API 直连。
- 代理池为空时自动直连，不阻断提链任务。

## 请求流程

1. WebUI 将勾选的账号按每批 `1-5` 个拆分。
2. 每个 Kakao 批次创建 client 时调用一次 `config.proxy.pick_proxy()`。
3. 同一批次的提交请求和所有结果轮询固定使用该代理，不在轮询中途更换出口。
4. 下一个批次重新从代理池抽取，从而支持动态代理和 `{sid}` 会话占位符。

## HTTP 实现

- `curl_cffi` 路径通过请求的 `proxy` 参数传入选中代理。
- 标准库兜底路径使用 `ProxyHandler` 和专用 opener，保持 HTTP/HTTPS 行为一致。
- client 内只保存本批次的代理，不修改全局系统代理。

## 日志与安全性

- 日志只标记本批次为 `proxy` 或 `direct`。
- 如需输出代理地址，必须遮罩用户名和密码。
- 提链 API 错误信息继续使用现有脱敏逻辑，不将 CDK、Token 或代理凭据写入账号数据。

## 失败行为

- 代理池为空：直接直连。
- 抽取代理异常：记录警告并直连，不中断整批。
- 已抽取代理连接失败：按现有 Kakao 错误与轮询重试规则处理，不在本批次内悄然切换直连，避免提交与轮询路由不一致。

## 测试

- 默认配置为开启代理池。
- 开启时每批只抽取一次代理。
- 同一 client 的提交和轮询使用同一代理。
- 关闭开关或代理池为空时直连。
- `curl_cffi` 与标准库兜底路径均有代理传递测试。
- 错误文本不包含代理凭据、CDK 或 access token。

## 不在本次范围

- 不自动检测或切换代理国家。
- 不新增 Kakao 专用代理池。
- 不改动旧提链 provider 的网络路由。
